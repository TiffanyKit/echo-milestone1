# Milestone I Write-Up — Echo (Review & Sentiment Analyst Agent)

**What works:**
The agent runs end-to-end on a real input (Joe's Pizza, NYC) and produces a correct structured output. It calls a real tool (`fetch_business_reviews`) that returns genuine Google Places review text, loops with a reasoning step before and after the tool call, and enforces a stop condition: a minimum-review threshold combined with a 3-iteration max guard. I verified the guard actually fires — running the agent on a business not in the dataset correctly triggers 3 retry attempts, then halts and reports "insufficient data" instead of looping forever or fabricating an answer. Theme extraction (food quality, service, wait time, price, cleanliness) and per-theme sentiment scoring both ran correctly on all 5 real reviews, and the final answer is grounded directly in the counted data (e.g., "Food Quality: mentioned in 4 review(s), positive: 4"), not a free-text LLM summary that could drift from the source.

**What does not work yet:**
Running a second, local Atlanta restaurant (Mary Mac's Tea Room) exposed a concrete bug: a glowing review praising "friendly and attentive wait staff" was scored negative, because the keyword lexicon substring-matches "wait" as a negative word and also tagged it as a wait-time theme. Both the sentiment and theme matching need word-boundary matching and context, which is a good argument for moving the analysis step to an LLM in Milestone II.

Sentiment scoring is currently a simple keyword lexicon applied to the whole review, not theme-specific — so a review that complains about wait time but praises the food nets out "positive" overall rather than flagging the wait-time complaint as negative on its own. This is the single biggest gap before Milestone II. The tool is also reading from a locally cached JSON file (containing real, live-fetched review data) rather than calling the Google Places API directly at runtime, since this sandbox has no outbound network access — the production `requests.get()` call is written and documented in the code but not exercised end-to-end yet.

**What I'll do next:**
For Milestone II, I'll split this single agent into the full planned pipeline (Fetcher → Theme/Sentiment Analyst → Trend Agent → Competitor Comparator → Report Drafter → Critic), move sentiment scoring to be theme-scoped rather than whole-review, and swap the cached-file tool call for a live Google Places API call using an actual API key. I'll also add the Critic agent's verification step so every claim in the final report is checked against the raw counts before being shown to the user, closing the main reliability gap in this version.
